# 固定版本协议笔记

以下字段来自本工程现有解析器，只适用于已经识别的格式。源码是精确边界，本文不是完整协议定义。

## 传输层

- payload[1] 的低四位区分本实现接受的两类传输帧。
- 首字节校验由帧长度、标志及序号字节共同确定，见 GameDecoder.checksum。
- 完整下行帧应用偏移为 10；完整上行帧应用偏移为 14。
- 解压前检查压缩标志；zstd 输出有大小限制。
- GameDecoder 支持已有的合并帧拆分与分片重组；改写器只处理自己已验证支持的完整帧。不要把解码能力等同于改写能力。

## 应用消息

| 消息 | 用途 |
| --- | --- |
| 3/1 | 登录、本地身份与初始玩家名单 |
| 3/3、3/6 | 玩家名单及移除更新，按解析器分支处理 |
| 3/2005 | 本地身份补充 |
| 3/2055 | 视角请求或确认，方向不同含义不同 |
| 上行 3/851 | 视角等向量，field 3 用于方向 |
| 下行 3/852 | 实体和动作列表 |

## 场景与动作

场景 field 6 是实体记录。实体 field 1=id1，field 2=id2，field 3=category，field 4=动作列表。演员类别由现有代码按 category=4 匹配。

动作 field 1=kind，field 2=scale，field 3=整数列表（支持已识别的 packed/unpacked 形式），field 4=附加字节。

| kind | 当前用途 |
| --- | --- |
| 1 | Position，三个坐标分量 |
| 2 | Rotation，四元数 x/y/z/w |
| 7 | Speed，已有状态语义 |
| 16 | Move，已有状态语义 |
| 31 | HP |

位置按动作自身 scale 解码。场景动作的 Int64 列表和上行视角向量编码不同；`GameDecoder.vector` 中的定制 wire 处理不能替换为普通 protobuf 库的 fixed32 读取。未知字段或未经验证格式不强行改写。

不要把 id2、UID、配置 ID 或会话实体编号混作同一标识。实体身份、连接和登录时间一起决定可用状态。
